# Глосар за собственика

Термините са обяснени за работа с проекта; техническите правила остават в свързаните авторитетни документи.

| Термин | Значение |
| --- | --- |
| **commit** | Записана, именувана промяна в Git историята. |
| **branch** | Изолирана линия за работа по задача, преди промяната да се предложи за основния код. |
| **PR (Pull Request)** | Предложение за преглед и сливане на branch. |
| **CI (Continuous Integration)** | Автоматични проверки на кода, изпълнявани от GitHub. |
| **SHA** | Уникалният идентификатор на точната версия (commit), която се проверява или одобрява. |
| **migration** | Версионирана контролирана промяна на структурата или данните в база. |
| **rollback** | Връщане към безопасна предишна версия по контролирана процедура. При Admin това е нова чернова, за да се пази историята. |
| **RLS (Row Level Security)** | Правила в PostgreSQL/Supabase, които ограничават кои редове данни може да чете или променя даден потребител. |
| **secret** | Чувствителна стойност, например token, парола, ключ или recovery code. Не се изпраща в чат, не влиза в Git или публична документация и не се показва в публичния сайт/Admin UI, браузърния код/изход или screenshots. Въвежда се ръчно само директно в официална форма на доставчик или в Bitwarden. |
| **environment (среда)** | Отделен контекст за Local, Staging или Production, със собствени данни и достъп. |
| **backup** | Проверено копие на данни, предназначено за възстановяване. |
| **restore** | Възстановяване на данни от backup в контролирана среда и проверка, че резултатът е годен. |
| **deploy** | Публикуване на проверена версия на приложението в конкретна среда. |
| **Local** | Работна среда на компютъра с локална база и синтетични данни. |
| **Staging** | Отделна защитена хоствана среда за проверка преди Production. |
| **Production** | Публичната работеща среда; промени в нея изискват изрично одобрение на собственика. |
| **GitHub** | Услугата за Git хранилището, PR и CI. |
| **Cloudflare** | Слоят пред приложението за доставка, защита и отделни хоствани цели. |
| **Supabase** | Услугата за PostgreSQL и входа на собственика за бъдещия Admin. |
| **Admin** | Бъдещ собственически интерфейс за бизнес данни и безопасни версии, не за инфраструктурни или account операции. |
| **Cloudflare Access** | Защита, която ограничава достъпа до Staging. |
| **noindex** | Инструкция Staging да не се добавя в търсачки. |
| **Phase Brief** | Одобреният пакет, който определя цел, обхват, проверки и граници на конкретна фаза. |

[Ръководство за собственика](OWNER_GUIDE_BG.md) дава общата картина, а [Day Zero setup](DAY_ZERO_SETUP_BG.md) е каноничният запис на действията от Phase 1.
